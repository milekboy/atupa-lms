# ATUPA MVP verification matrix

Baseline date: 2026-10-16 (Africa/Lagos). No frontend feature is implemented by this document. Saved Postman examples are distinct from live checks. Role labels below express intended access plus the collection's sampled token; they do not prove every server permission.

API base: `https://atupa-lms-backend.onrender.com/api/v1`. All backend paths are relative to this base. All criteria are **not functionally verified** unless separately recorded in live-check evidence. `01` etc. refer to collection folders in the endpoint inventory.

## Scope baseline

Required: US-01–US-16, basic US-18, US-19 and PRD section 34's 16 must-haves. US-09 integration details remain a product/backend dependency. US-17 full search is P2, pending inclusion. US-20 payments are conditional, pending inclusion. Neither conditional item has been silently accepted or permanently deferred. Phase 2 excludes live classes, AI tutoring, automated pronunciation assessment, advanced analytics/gamification, native apps and additional-language rollout.

## Cross-cutting definition of done

Every criterion also requires correct role access, direct-URL/API denial for unrelated users, useful validation/errors, persistent saved state, relevant responsive sizes, and product-owner acceptance. Security/session design belongs to step 3; keyboard/contrast/media/performance checks to steps 2 and 21. Password hashing, database protection and backend scalability cannot be established from a frontend collection alone.

## Test accounts and ownership baseline

No isolated accounts or credentials were supplied or provisioned during this baseline. All six roles remain **unconfirmed**. Do not reuse recorded Postman tokens/IDs as credentials or execute the collection's cleanup folder against shared data.

| Role | Required isolated fixtures | Positive check | Negative check |
| --- | --- | --- | --- |
| learner | Two learners in school A, one in school B | Enroll/complete own work; create parent link | Cannot read another learner report or author solutions |
| parent | One linked parent and unrelated parent | Read linked child dashboard | Cannot link by guessed ID or read unlinked child |
| teacher | Two teachers with distinct owned courses/classes | Manage own class/course; review assigned learner | Cannot mutate another teacher/school content unless explicitly granted |
| school_admin | School A admin and school B fixtures | Invite/remove own members and assign teachers | Cannot administer school B |
| content_creator | Privileged invitation required | Verify permitted content operations | Cannot manage users/schools without explicit grant |
| super_admin | Backend-owner supplied isolated account | Platform admin operations on isolated data | Public registration cannot create privileged roles |

Use an approved local secret store or a gitignored environment file for future test credentials; record only non-secret fixture labels here. Ask the backend owner to confirm role grants, same-school membership prerequisites, standalone-teacher class rules, course ownership, visibility of published content, and who may invite each role. The collection shows example tokens, not an exhaustive authorization policy.
